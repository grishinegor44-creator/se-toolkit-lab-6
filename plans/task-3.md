# Task 3 Plan

## Goal

Добавить в агента новый инструмент `query_api`, чтобы он мог обращаться к развернутому backend API и отвечать не только по wiki и исходному коду, но и по данным системы.  
Также нужно обновить системный промпт и конфигурацию агента так, чтобы все параметры читались из переменных окружения.

## What I will implement

### 1. Add `query_api` tool schema

Я добавлю новый function-calling tool `query_api` в `agent.py`.

Параметры инструмента:
- `method` — HTTP-метод (`GET`, `POST`, etc.)
- `path` — путь API, например `/items/`
- `body` — необязательное JSON-тело запроса в виде строки

Возвращаемое значение:
- JSON-строка с полями:
  - `status_code`
  - `body`

## API authentication

Для запросов к backend я буду использовать `LMS_API_KEY` из переменных окружения.  
Ключ должен браться из окружения, а не быть захардкожен в коде.

План:
1. Прочитать `LMS_API_KEY` через `os.getenv(...)`.
2. Прочитать `AGENT_API_BASE_URL` через `os.getenv(...)`.
3. Если `AGENT_API_BASE_URL` не задан, использовать значение по умолчанию: `http://localhost:42002`.
4. При выполнении `query_api` добавлять ключ в заголовки аутентификации.
5. Возвращать в агент только краткий и понятный результат запроса: статус и тело ответа.
